- 统一采用VerifiedV08Replay，持仓缺失报价、无法解释的参考价调整及公司行动问题必须拦截。公司行动先规范去重；无法解决的重复事件直接拒绝运行。
- 所有账户使用相同日期、初始3万元、费用/T+1/涨跌停等执行约束，默认现金收益为0；统一实际日期跨度年化、无风险利率0的夏普口径。无交易胜率和不可定义指标为空。原引擎文件未修改，其他研究和DAY1运行不受影响。
- 同风险轨道：V2、V3、V0.8均用动态5500/7500预算、同一仓位上限与退出规则，避免将风险预算差异算成选股能力。V7使用V2信号，因此同风险轨道不重复一个相同选手。
- 原配置轨道：V5/V6使用5000预算、4持仓及65%暴露上限，V7/V0.8使用动态配置；统一质量检查，但与同风险轨道分开展示。原配置没有与同风险随机账户混合排名。
- 同风险每个模型每个时期请求20个固定种子的随机账户，使用相同预测候选全集，匹配信号日期和每日候选数量，执行规则完全相同。V2和V0.8门控相同，随机账户也相同，是配对对照，不是额外独立样本。随机交易成交数、预算使用率并未被强行匹配，因此不能把差值理解为纯排名因果效应。
- 每个模型另有双倍滑点场景。压力测试会改变现金、整手数量和之后的成交路径；不能保证收益单调下降。
- 删除不可执行的“300股票买入持有”及伪造的平仓数300、现金100%胜率和固定99指标。当前可执行基准为同引擎现金账户。需要市场基准时，应另行加入明确指数参考或真实ETF账本，不能冒充3万元可执行的300股组合。
- 可选固定现金年利率使用同一个公式、同样首日计息。明确只是现金利率假设，不声称模拟GC001实际订单。
- 每次运行使用唯一目录；两个时期分目录，逐账户保存signals、fills、trades、equity、actions、holdings、warnings、review_warnings及summary。失败场次保存部分账本及失败原因，不补种子、不覆盖负结果。
- 保存实际依赖源码快照、输入哈希和种子；数据加载检查原始行情及公司行动哈希，结束时检查评测源码与输入未变化。无关且未被导入的工作文件不纳入源码冻结。
- 已实现run、leaderboard、dashboard三个命令；自定义日期有效，与固定时期参数冲突时明确拒绝。全部输入相对脚本定位，可从其他目录启动。

## 使用

在项目目录使用本地Python：

```powershell
.\.venv\Scripts\python.exe arena.py run
.\.venv\Scripts\python.exe arena.py leaderboard
.\.venv\Scripts\python.exe arena.py dashboard
.\.venv\Scripts\python.exe arena.py run --start 2024-01-01 --end 2024-12-31
.\.venv\Scripts\python.exe arena.py run --mode 2026 --cash-rate 0.022
.\.venv\Scripts\python.exe -m unittest test_arena test_v08_verified -q
```

默认run运行两个时期。可用--output指定一个尚不存在的新目录；阅读命令的--output则指定已有运行。默认随机种子20个，--random-count仅供缩短开发检查，不能挑选有利种子。现金利率/候选门槛没有根据此次收益调优。

旧输出保留为历史资料，根目录旧版leaderboard.csv不再是当前榜单，以新运行目录为准。第一次开发运行保存于run-20261020T145741045563Z；第二轮run-20261020T145855351728Z因无关trader_bridge.py变化被过宽的完整性检查拒绝封存，故没有summary.json；两者均未删除。最终运行仅冻结竞技场实际依赖，完整性检查通过。
